# Чек-лист организатора — статус и QA-гейт до мержа

**Источник:** письмо Ярослава (текущий статус + чёткий план действий).  
**Что не решено по бэкенду (следующие спринты):** `docs/BACKEND_TODO_AFTER_CHECKLIST.md`

---

## 0) Правило скоупа (обязательное)

Работаем **строго** в рамках 3 направлений:

1. **Чек-лист организатора**
2. **Wake Challenge (WSC)**
3. **WakeSurf Safari**

Любые «попутные» правки главной/услуг/магазина/чата/аналитики/рекомендаций/прочего — **запрещены**. Раздел «Проекты» (карусель + модалка) — отдельное направление, реализуется **после** чек-листа и **после** WSC → Safari.

---

## 1) Статус по Чек-листу (принято)

- Ветка **`feature/contest-org-checklist-final`** создана от `main`, содержит **1 коммит только по чек-листу**, **запушена в `origin`**.
- В коммите только:
  - `app/__init__.py` — регистрация blueprint'ов чек-листа и редиректного wake_industry
  - `app/routes/contest_org_checklist.py`
  - `app/routes/wake_industry.py` (только 301 на каноник)
  - `templates/base.html` (блок `body_class`)
  - `templates/projects/contest_org_checklist/` (все шаблоны)
  - `static/css/style.css` (print-стили изолированы под `body.project--contest-org-checklist`)
  - `configs/showcases/contest_org_checklist.yaml`
  - документы для PR и следующего спринта (по списку в `docs/SUBAGENTS_ASSIGNMENT_AND_SKILLS.md`, п. 3).

## 2) СРОЧНО: PR + QA-гейт (мерж только после QA)

### 2.1 Subagent A — PR (обязательный шаг 1)

**Задача:** создать PR: `feature/contest-org-checklist-final` → `main`.

- Ссылка на создание PR: см. `docs/PR_DESCRIPTION_READY_TO_COPY.md` (или вывод GitHub "Create PR").
- В PR: **заголовок и Description** — из подготовленных docs (готовый текст в `docs/PR_DESCRIPTION_READY_TO_COPY.md` и `docs/PR_CONTEST_ORG_CHECKLIST.md`).
- В diff должно быть **только то, что относится к чек-листу** (никаких «случайных» файлов).

**DoD A:**
- [ ] PR создан, ссылка отправлена Ярославу.
- [ ] Заголовок/описание вставлены из `docs/PR_DESCRIPTION_READY_TO_COPY.md`.
- [ ] В PR **только** файлы чек-листа (никаких правок вне скоупа).

**Ответственный за артефакт:** Subagent A → **ссылка на PR**.

---

### 2.2 Subagent E — QA (обязательный шаг 2)

**Задача:** полный прогон QA по `docs/QA_PROTOCOL_CONTEST_ORG_CHECKLIST.md`.

**Артефакты E:**
1. 6–10 скриншотов (верх/середина/низ страницы, интерактивность, консоль)
2. 1 итоговый PDF с `/projects/contest-org-checklist/download`
3. Заполненный чек-лист «ОК/не ОК»
4. (опционально) короткое видео флоу: страница → download → открытие PDF

**DoD E:**
- [ ] Одна строка вердикта: **«блокеры = 0»** или список блокеров.

**Ответственный за артефакты:** Subagent E → **QA-пакет** + **строка «блокеры = 0»** (или список блокеров).

**Подготовка (сделано агентом):** инструкция и шаблон вердикта для прогона QA — `docs/QA_PACKAGE_AGENT_PREP.md`. QA выполнять на ветке из PR (`feature/contest-org-checklist-final`), в текущей ветке blueprint чек-листа отсутствует.

---

### 2.3 Subagent D — print-изоляция (обязательный шаг 3)

**Задача:** проверить, что print-стили влияют только на страницу чек-листа и не ломают печать других страниц.

**Проверка:**
- Печать **другой страницы** (например, главной): шапка/футер/контент остаются, ничего не исчезает.
- Печать **чек-листа**: печатается только контент без навигации/кнопок.

**DoD D:** скрин/видео print preview (DevTools) для чек-листа и для любой другой страницы (например, главной).

**Ответственный за артефакт:** Subagent D → **подтверждение print-изоляции** (скрин/видео).

---

### 2.4 Subagent F — SEO-регресс (обязательный шаг 4)

**Задача:** коротко проверить canonical/meta/OG и отсутствие регресса от правок чек-листа.

**DoD F:** короткий отчёт (что проверено + вывод).

**Ответственный за артефакт:** Subagent F → **отчёт SEO** (коротко).

---

### 2.5 Subagent B — on-call (только если QA выявит)

**Задача:** подключаться **только** если QA покажет проблемы:
- PDF не строится (WeasyPrint/зависимости)
- В PDF не резолвятся картинки (base_url)
- Вместо 503 при отсутствии WeasyPrint получаем 500/500-серии

## 3) Правило мержа (1.6)

**Мерж в main делаем только при выполнении:**
- есть ссылка на PR
- есть QA-пакет
- есть строка **«блокеры = 0»**

Иначе — фиксируем блокеры, чиним, повторяем QA. После мержа: фиксируем «Чек-лист закрыт 10/10», стартуем спринт Wake Challenge (DoD 10/10), затем WakeSurf Safari, затем раздел «Проекты».

---

## 4) Что прислать Ярославу следующим сообщением (строгий порядок)

1. **Ссылка на PR** чек-листа (`feature/contest-org-checklist-final` → `main`)
2. **QA-пакет** от Subagent E + строка **«блокеры = 0»** (или список блокеров)
3. **Если блокеры = 0** — пакет файлов Wake Challenge для точечного патч-плана (по списку в docs)

После этого начинаем спринт Wake Challenge (DoD 10/10), затем WakeSurf Safari, и только потом — раздел «Проекты».
