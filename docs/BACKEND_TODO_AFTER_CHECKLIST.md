# Что НЕ решено по бэкенду (закрывается в следующих спринтах)

**Правило скоупа:** работаем строго в рамках Чек-лист / Wake Challenge / WakeSurf Safari (+ раздел «Проекты» только после WSC → Safari). Никаких попутных правок главной/услуг/магазина/чата/аналитики/рекомендаций.

---

## 1) Wake Challenge (WSC) — бэкенд-хвосты

Есть роут/формы/сервис, но «не закрыто» до патч-плана и прогона:

- Неработающие CTA/табы/submit (в т.ч. 400/CSRF)
- Корректные сценарии по ролям (участник/тренер/спонсор)
- Canonical/meta на канонический домен

**Закрытие:** после мержа чек-листа — пакет файлов Wake Challenge по `docs/WAKE_CHALLENGE_FILES_FOR_PATCH_PLAN.md` → точечный патч-план от Ярослава → спринт DoD 10/10.

---

## 2) WakeSurf Safari — бэкенд-хвосты

- При необходимости — расширение/добавление эндпоинтов под лид-форму и партнёрские интеграции
- Canonical/meta для страницы Safari (если ещё не отдаются с бэкенда)

**Закрытие:** спринт Safari после Wake Challenge.

---

## 3) Раздел «Проекты» (Вариант 1) — бэкенд-хвосты данных витрины

Бэкенд-задача: расширить источник данных проектов (YAML/сервис) под фронт:

- `gallery[]` — минимум 3 изображения на проект
- `modal_content` — полный текст для модалки
- `primary_actions[]` — CTA для модалки
- `page_url` — канонический URL страницы проекта

И убедиться, что главная и `/projects` рендерят **один и тот же** список с нужными полями.

**Закрытие:** реализация раздела «Проекты» **после** чек-листа и **после** WSC → Safari. Frontend (Subagent G) — карусель, свайп vs клик, мини-галерея, модалка (a11y, scroll lock, focus trap).
