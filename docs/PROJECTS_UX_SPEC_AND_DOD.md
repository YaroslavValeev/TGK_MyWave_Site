# Раздел «Проекты» — UX/IA спецификация и Definition of Done

**Дата:** 2026-02-04  
**Источник:** фиксация от Ярослава (эталон UX и DoD для реализации без «догадок»).  
**Принято как единый источник истины (Ярослав, 2026-02-04).** Реализация — **после закрытия чек-листа** и по очереди **после Wake Challenge → WakeSurf Safari** (дорожная карта).

---

## 1) Эталон поведения (как было и как должно снова стать)

1. **Главная:** все 5 проектов сразу в блоке «Проекты», листаются в **карусели** (десктоп: ползунок + полупрозрачные стрелки; мобилка: свайп).
2. **Клик по карточке** → карточка раскрывается в **модальное окно** с полным текстом и всеми функциями проекта.
3. **В карточке** можно листать фото **внутри карточки** (мини-галерея). То же — **внутри модалки** (галерея продолжается/расширяется).
4. В модалке (и при необходимости на карточке) есть **кнопка перехода на страницу проекта**.

---

## 2) Состав и единый источник

- Ровно **5 проектов:**
  1. WSC 2026 (WakeSurf Coach Challenge)
  2. WakeSurf Safari
  3. Чек-лист организатора соревнований
  4. Индустрия Wake
  5. Летний лагерь
- **Единый источник данных** для витрины проектов (не «часть в шаблоне, часть в yaml»).
- Главная секция «Проекты» и страница `/projects` рендерят **один и тот же список** из одного источника.
- В каждом проекте: `title`, `slug`, `summary`, `gallery` (массив путей, минимум 3), `modal_content` (полный текст), `page_url` (каноник), `primary_actions` (CTA: «Оставить заявку», «Скачать», «Связаться» и т.п.).

---

## 3) Главная: карусель проектов

**Визуально/управление:**
- Горизонтальная карусель из 5 карточек.
- Кнопки навигации: полупрозрачные (без «круга как в 2008»), с hover-состояниями.
- Плюс ползунок (range) для точной прокрутки.
- На мобилке — свайп, стрелки можно скрывать/уменьшать.

**Поведение:**
- Прокрутка «по карточкам» (snap), чтобы всегда аккуратно становилось на начало карточки.
- Карусель не должна ломать CLS/верстку при загрузке картинок.

---

## 4) Карточка проекта: внутренняя мини-галерея

**Внутри карточки:**
- Мини-галерея (несколько фото) — листается: мобилка — свайп по фото; десктоп — стрелки + (опционально) точки-индикаторы.
- В карточке: название, короткий summary (2–3 строки), один «крючок» (формат/даты/главная ценность).

**Критично (конфликт свайп vs клик):**
- **Свайп по фото** листает фото и **не** открывает модалку.
- **Клик (tap) по свободной зоне карточки** открывает модалку.
- **Клик по элементам галереи** (стрелки/точки) **не** открывает модалку.

---

## 5) Модальное окно проекта

**Модалка должна уметь:**
- Открытие по клику на карточку.
- Закрытие: крестик, клик по оверлею, клавиша Esc.
- Фокус-ловушка (keyboard), блокировка прокрутки body.
- Адаптив: на мобилке — полноэкранная, на десктопе — «центр + много воздуха».

**Содержимое (универсальный паттерн):**
1. Заголовок проекта  
2. Галерея проекта (больше, чем в карточке; листается)  
3. Полный текст/описание  
4. Блок «действия/функции» (CTA-кнопки/ссылки/формы)  
5. **Кнопка «Перейти на страницу проекта»** (явная, видимая)

**Вариант реализации (зафиксирован):**
- **Вариант 1 (принят):** модалка = полный текст + ключевые CTA (скачать/заявка/связаться) + кнопка «на страницу проекта». Все сложные формы/многошаговые сценарии — только на странице проекта (не плодим логику внутри модалки).
- ~~Вариант 2~~ (не выбран): в модалку подгружается «полная страница проекта» — не реализуем.

**Кратко по Варианту 1 (что сохраняем/возвращаем, эталон для реализации):**
- **Главная:** все 5 проектов в карусели (ползунок range, полупрозрачные кнопки стрелок; мобайл — свайп). Внутри каждой карточки — мини-галерея фото (листать в карточке). Клик на карточку (не на элементы галереи) → карточка раскрывается в модалку.
- **Модалка:** полный текст проекта, ключевые CTA, галерея листается (продолжение без разрыва), **кнопка «Перейти на страницу проекта»** обязательна (ведёт на `/projects/<slug>`).
- **Правило:** сложные формы и многошаговые сценарии (регистрация/оплата/документы) — только на странице проекта; модалка = быстрый просмотр + CTA + переход.

---

## 6) Страница `/projects` и страницы проектов

- `/projects` — полноценная витрина (SEO/доступность); grid или тот же карусель-паттерн; UX консистентен с главной.
- Каждая страница проекта (`/projects/<slug>`) — главный SEO-якорь и точка входа из поиска/шеров.
- Модалка — UX-ускоритель, **не замена** страниц; не создаёт дублей/индексации (не URL-страница).

---

## 7) Техническая реализация (без внешних CDN, с учётом CSP)

**Переиспользовать:**
- Паттерн модалки из `catalog-modal.js` (открытие/закрытие/оверлей) — адаптировать под проекты.
- Паттерн горизонтальных каруселей (reviews/events/blog) — расширить на Projects.
- Витринные YAML-конфиги проектов — расширить полями галереи.

**Добавить (минимально):**
- **JS:** `projects-carousel.js` (карусель главной: стрелки + range + snap), `project-modal.js` (модалка + контент/галерея), при необходимости `project-media-carousel.js` (мини-галерея в карточке и галерея в модалке; можно объединить с modal).
- **CSS:** стили «projects-carousel», «project-card», «project-modal», «project-gallery»; изоляция, чтобы не поломать услуги/магазин/блог.

---

## 8) Definition of Done — раздел «Проекты»

- [ ] Единый источник 5 проектов: главная и `/projects` рендерят один список.
- [ ] Карусель на главной: 5 карточек, стрелки + range + snap; мобилка — свайп.
- [ ] В карточке: мини-галерея (листается); свайп по фото не открывает модалку; клик по карточке открывает модалку.
- [ ] Модалка: открытие/закрытие (крестик, оверлей, Esc), фокус-ловушка, блокировка scroll body; полный текст + галерея + CTA + кнопка «Перейти на страницу проекта».
- [ ] Консоль без ошибок; сеть без 404 по картинкам; регресс по reviews/events/blog и другим секциям отсутствует.
- [ ] `/projects` и `/projects/<slug>` — корректные meta/canonical/OG; модалка не создаёт индексируемых дублей.
