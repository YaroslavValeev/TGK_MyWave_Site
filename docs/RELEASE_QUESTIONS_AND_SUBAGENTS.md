## QUESTIONS TO DEV (ответы по коду)

### 1. Где формируется img для карточек витрины на главной: это products_preview.image или хардкод в шаблоне?

**Ответ:** Из данных. Изображение берётся из **`products_preview`**: у каждого элемента есть поле **`image`** (например `images/balans_trick_trening1.jpg`). Формирование списка — в **`app/routes/shop.py`**: функция **`get_products_preview(6)`** по списку slug’ов `PRODUCTS_PREVIEW_SLUGS` подставляет из словаря **`PRODUCTS`** объекты с полями `title`, `price`, `description`, **`image`**. В шаблоне **`templates/index.html`** (блок «Товары») используется только это:  
`<img src="{{ url_for('static', filename=p.image) }}" ...>`. Хардкода путей к картинкам в шаблоне нет.

**Правка:** В шаблон добавлен fallback: при отсутствии `p.image` подставляется `images/hero-wakesurf.webp`, плюс `onerror` на теге `<img>`, чтобы при 404 подставлялась та же заглушка (без серых прямоугольников).

### 2. Почему в магазине настолка называлась "Wave Cards": это отдельный товар или ошибка нейминга?

**Ответ:** Это была **ошибка нейминга и дублирование**. В каталоге были два объекта: slug **`wave-cards`** с названием «Настольная игра «Wave Cards»» и slug **`wakesurfpolia`** с названием «WakeSurfPolia». По ТЗ канон один — **WakeSurfPolia**. Внесены изменения: товар **`wave-cards`** удалён из **`PRODUCTS`** в `app/routes/shop.py`; единственная настольная игра — **`wakesurfpolia`** (название «WakeSurfPolia», описание про игру). В **`templates/shop.html`** убрана карточка «Wave Cards», фильтр «Настольные игры» заменён на одну категорию **WakeSurfPolia**; везде отображается только «WakeSurfPolia».

### 3. "Купить" на главной: сейчас это линк на /shop/product/... или кнопка под JS? Где задано поведение?

**Ответ:** Это **ссылка**, не кнопка под JS. В **`templates/index.html`** в блоке «Товары» для каждой карточки:  
`<a class="btn-secondary btn" href="{{ url_for('shop.product', slug=p.slug) }}">Купить</a>`.  
Поведение: переход на страницу товара **`/shop/product/<slug>`**. Роут и view — **`app/routes/shop.py`**: `@shop_bp.route("/product/<slug>")`, шаблон **`shop_product.html`**. На странице товара кнопка «Купить» пока ведёт на `#` (заявку/оформление при необходимости можно добавить отдельно).

---

### 4. Скрин/факт: секция «Проекты» на главной и страница /projects (200).

**Ответ:** По коду: на главной секция «Проекты» рендерится в **`templates/index.html`** (блок `#projects`): данные **`projects_preview`** из **`app/__init__.py`** (index view), плюс карточка «Тренировочная программа для подготовки» и ссылка «Все проекты» на **`url_for('projects_page')`**. Страница **`/projects`** отдаётся view **`projects_page()`** в **`app/__init__.py`** (GET, 200 при успехе; при ошибке загрузки showcase отдаются пустые списки, но ответ 200). Фактический скрин 200 и контент нужно снять вручную (Subagent B / A).

---

### 5. Скрин/факт: блок «Последние новости» на главной (последний пост + ссылка).

**Ответ:** По коду: блок в **`templates/index.html`** (секция `#blog`): переменная **`latest_blog_post`** из **`app/__init__.py`** (index). Если пост есть — выводится заголовок (ссылка на `blog.blog_post` по slug), опционально excerpt и ссылка «Все статьи блога» на **`blog.blog_index`**. Скрин с реальным последним постом — вручную (Subagent B / A).

### Subagent B — Frontend QA  
**Skills:** DevTools triage, template tracing  

**Найденный источник плейсхолдеров:**  
- **Файл:** `templates/index.html`, блок «Товары» (`.store-section .cards-grid`).  
- **Данные:** `products_preview` из `get_products_preview(6)` в **`app/routes/shop.py`**; у каждого элемента поле **`image`** (путь вида `images/...`).  
- **Почему img пустой/серый:** при 404 по `p.image` или при отсутствии файла на диске браузер показывал пустую рамку; fallback в шаблоне не было.  
- **Правка:** добавлены `p.image or 'images/hero-wakesurf.webp'` и `onerror="... this.src='...hero-wakesurf.webp';"` для всех карточек товаров на главной; аналогичный fallback в **`templates/shop_product.html`**.

**Вернуто:** файл → блок → причина → правка (см. выше).
