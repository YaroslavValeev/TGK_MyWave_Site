# Письмо команде ParserNews: лист `competitions_ticker` (бегущая строка соревнований)

**Тема письма:** `[MyWave Site] Контракт листа competitions_ticker — бегущая строка соревнований (вейксерф / вейкборд)`

**Кому:** команда ParserNews / Parser Bot  
**Копия:** владелец продукта MyWave, разработка Site_MyWave  
**Приоритет:** средний (блокер для витрины — наполнение листа; код сайта уже готов)

---

Здравствуйте, коллеги!

На стороне **Site MyWave** (mywavewake.ru) реализована **бегущая строка** на главной странице: между блоками «Проекты» и «Блог» отображаются **предстоящие и текущие** соревнования по **вейксерфингу и вейкборду** по всему миру. Строка кликабельна — ведёт на официальную страницу события.

Данные сайт **не парсит сам** и **не смешивает с блогом**: источник — **новый лист** в **той же Google-таблице Parser News**, которую вы уже используете для `raw_feed`. Ниже — полный контракт, ожидания по источникам и критерии приёмки.

---

## 1. Контекст и разделение с блогом

| Назначение | Лист | Содержимое |
|------------|------|------------|
| Блог, статьи, новости | `raw_feed` | Тексты, slug, статусы `READY_TO_PUBLISH` / `PUBLISHED` (контракт v1 — без изменений) |
| Бегущая строка соревнований | **`competitions_ticker`** | События с **датами**, локацией, дисциплиной, ссылкой на регистрацию/анонс |

**Важно:** календарные события с `start_date` / `end_date` пишем в **`competitions_ticker`**, а не в `raw_feed`. Новостные материалы без роли «событие в календаре» — по-прежнему в `raw_feed`.

Старый лист `events_calendar` (если у вас используется) **сайт для ticker не читает** — только `competitions_ticker`.

## 3. Схема колонок

### 3.1. Обязательные (строка 1 — точные имена)

```
id | status | discipline | event_name | location | country | start_date | end_date | event_url | source_name | source_url | updated_at
```

| Колонка | Тип | Правила |
|---------|-----|---------|
| `id` | string | Стабильный ключ: UUID или `{source}_{external_id}`. **Upsert по `id`**, без дублей строк |
| `status` | enum | `ACTIVE` — показывать на сайте; `DRAFT` — черновик/модерация; `ARCHIVED` — скрыть с витрины |
| `discipline` | enum | Строго: `wakesurf` \| `wakeboard` \| `both` |
| `event_name` | string | Название соревнования (обязательно для показа) |
| `location` | string | Город / регион |
| `country` | string | Страна (текст или код: `USA`, `Россия`, …) |
| `start_date` | date | Только **`YYYY-MM-DD`** |
| `end_date` | date | **`YYYY-MM-DD`**; однодневное событие: **`end_date = start_date`** |
| `event_url` | url | Официальная страница регистрации/анонса — **приоритетная ссылка** в бегущей строке |
| `source_name` | string | Человекочитаемый источник (IWWF, WSWS, WWA, …) |
| `source_url` | url | URL страницы источника (fallback для клика, если `event_url` пуст) |
| `updated_at` | datetime | ISO 8601, обновлять при каждом изменении строки |

### 3.2. Рекомендуемые (для вашего pipeline)

| Колонка | Назначение |
|---------|------------|
| `ingest_status` | `new` / `parsed` / `error` (по аналогии с `raw_feed`) |
| `ingest_error` | Краткий текст ошибки парсинга |
| `checksum` | Хеш содержимого для идемпотентного upsert |
| `raw_title` | Оригинальный заголовок с сайта-источника |
| `ticker_text` | **Готовая однострочная подпись** для marquee; если пусто — сайт соберёт строку сам (см. §4) |

## 4. Что именно показывает сайт (Ticker Contract v1)

Строка попадает в бегущую ленту **только если выполнены все условия:**

1. `status` = **`ACTIVE`** (без учёта регистра, case-insensitive)
2. **`end_date` ≥ сегодня** (дата UTC на сервере) — только **предстоящие и идущие** соревнования
3. Заполнены **`event_name`** и валидный **`start_date`**
4. Есть кликабельная ссылка: нормализованный **`event_url`**, иначе **`source_url`** (должен начинаться с `http://` или `https://`)

**Сортировка на сайте:** `start_date` по возрастанию, затем `event_name`.

**Текст в строке:**

- Если заполнен **`ticker_text`** — используется он (рекомендуем для длинных названий).
- Иначе сайт собирает автоматически:

  `{дисциплина} · {event_name} · {location}, {country} · {даты}`

  Пример: `Wakesurf · IWWF World Championships · Orlando, USA · 12.06–15.06.2026`

**Поведение UI:** клик открывает `event_url` (или `source_url`) в новой вкладке. Если в таблице **нет ни одной** подходящей строки — блок на главной **не отображается** (пустой ticker не показываем).

## 5. Ожидания по источникам и охвату

Нужен максимально полный **мировой** календарь. Минимальный целевой список (можно расширять по мере подключения):

**Вейксерфинг:** IWWF (календарь/анонсы wakesurf), WSWS, WWA, CWSA, Федерация вейксерфинга России, национальные серии (USA, EU, AU, JP, BR и др.).

**Вейкборд:** IWWF wakeboard / cable, WWA wakeboard, The Wakeboard Tour, европейские и cable-соревнования.

Если источник **уже в pipeline блога** — разделяйте потоки:

- **Статья / новость / интервью** → `raw_feed`
- **Событие с датой начала/окончания и местом** → `competitions_ticker`

Не дублируйте одно и то же событие в оба листа без необходимости.

## 6. Операционные правила (Parser)

### 6.1. Запись и дедупликация

- **Upsert по `id`**: при изменении дат, статуса или URL — **обновление** существующей строки, не вставка дубликата.
- Дополнительно можно дедуплицировать по **`checksum`** (например, хеш от `event_name + start_date + location + source_url`).
- При отмене соревнования — `status` → **`ARCHIVED`** (не удалять строку без необходимости — для аудита).

### 6.2. Жизненный цикл по датам

- После наступления дня **`end_date + 1`** (или по вашему nightly job) — переводить строку в **`ARCHIVED`**, чтобы не засорять витрину.
- События «идут сейчас» (`start_date ≤ сегодня ≤ end_date`) остаются **`ACTIVE`** и видны на сайте.

### 6.3. Валидация перед `ACTIVE`

Перед выставлением `ACTIVE` проверяйте:

- `start_date` / `end_date` парсятся как `YYYY-MM-DD`
- `end_date` ≥ `start_date`
- `discipline` ∈ {`wakesurf`, `wakeboard`, `both`}
- `event_name` не пустой
- Хотя бы один из `event_url`, `source_url` — валидный URL

Иначе оставляйте **`DRAFT`** и заполняйте `ingest_error`.

### 6.4. Частота обновления

- Рекомендуем: **1–2 раза в сутки** (cron) + ручной прогон при добавлении нового источника.
- После **массового импорта** (>50 строк или первичное наполнение) — уведомить команду сайта для сброса кэша (см. §7).

## 7. Взаимодействие с сайтом после заливки данных

Сайт кэширует лист **5 минут** (`COMPETITIONS_SHEETS_CACHE_TTL=300`).

**Диагностика (read-only):**

```http
GET https://mywavewake.ru/api/competitions/ticker
```

Ответ (без PII): `items[]`, `count`, `spreadsheet_id_tail`, `sheet_name`, `hint`.

**Сброс кэша после bulk-update** (нужен секрет, тот же что для media upload):

```http
POST https://mywavewake.ru/api/competitions/cache/invalidate
Authorization: Bearer <MEDIA_UPLOAD_TOKEN>
```

Либо заголовок: `X-Media-Upload-Token: <MEDIA_UPLOAD_TOKEN>`.

Токен передаётся владельцу инфраструктуры отдельно; в таблицу и в git **не класть**.

**Проверка на главной:** https://mywavewake.ru/ — между «Все проекты» и «Блог» должна появиться горизонтальная полоса с бегущим текстом (после появления ≥1 строки `ACTIVE` с будущим `end_date`).

## 8. Критерии приёмки (Definition of Done)

### 8.1. Техническая приёмка (3 тестовые строки)

Добавьте в лист (даты подставьте относительно «сегодня»):

| id | status | discipline | event_name | location | country | start_date | end_date | event_url |
|----|--------|------------|------------|----------|---------|------------|----------|-----------|
| `test-ticker-1` | ACTIVE | wakesurf | Test Event Future | Orlando | USA | сегодня +30 дней | сегодня +33 дня | https://example.com/event1 |
| `test-ticker-2` | ACTIVE | wakeboard | Test Cable Contest | Berlin | Germany | сегодня +10 дней | сегодня +10 дней | https://example.com/event2 |
| `test-ticker-3` | ARCHIVED | both | Past Event | Moscow | Russia | сегодня −30 дней | сегодня −28 дней | https://example.com/event3 |

**Ожидание на сайте:**

- В API и на главной видны **только test-ticker-1 и test-ticker-2** (count = 2).
- **test-ticker-3** не отображается.
- Клик по строке ведёт на `event_url` из таблицы.

После приёмки тестовые строки можно перевести в `ARCHIVED` или удалить.

### 8.2. Продуктовая приёмка (пилот)

- Не менее **15–20** реальных событий `ACTIVE` с корректными датами (смесь wakesurf / wakeboard).
- Нет дублей по одному `id`.
- Нет «битых» дат и пустых `event_name` в статусе `ACTIVE`.

## 10. Вопросы и эскалация

При расхождении колонок, статусов или формата дат — **сначала** правим контракт в `COMPETITIONS_TICKER_CONTRACT_v1.md` и согласуем с Site, **потом** меняем прод.

Типовые вопросы, на которые уже есть ответ:

| Вопрос | Ответ |
|--------|--------|
| Отдельная таблица? | Нет, тот же Spreadsheet ID, лист `competitions_ticker` |
| Прошедшие соревнования? | `ARCHIVED` или `end_date` в прошлом — сайт скрывает |
| Несколько дисциплин в одном ивенте? | `discipline` = `both` |
| Длинное название? | Заполните `ticker_text` вручную или сократите `event_name` |
