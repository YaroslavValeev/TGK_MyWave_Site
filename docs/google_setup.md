# Настройка Google Service Account и отладка (Sheets / Drive / Calendar)

Этот документ описывает корректную настройку сервисного аккаунта Google, рекомендуемые значения окружения для разработки и способы работы в режиме mock, чтобы не блокировать локальную разработку.

## 1. Создание сервисного аккаунта

1. Перейдите в Google Cloud Console → IAM & Admin → Service Accounts.
2. Создайте сервисный аккаунт (например `mywave-dev-sa`).
3. На этапе создания назначьте роль `Editor` или более ограниченные роли: `Drive API`, `Sheets API`, `Calendar API` (для продакшна лучше давать минимально необходимые права).
4. Создайте ключ (JSON) и скачайте файл.

## 2. Размещение файла

- Поместите файл в `instance/service_account.json` или в любую удобную директорию и укажите путь через переменную окружения:

```powershell
# Windows (PowerShell)
$env:GOOGLE_SERVICE_ACCOUNT_FILE = "C:\path\to\service_account.json"
# or add to .env
```

- Файл не должен попадать в git.

## 3. Переменные окружения

Рекомендуемые переменные:

- `GOOGLE_SERVICE_ACCOUNT_FILE` — путь к JSON файлу ключа
- `SPREADSHEET_ID` — id таблицы для логов/заявок
- `DRIVE_FOLDER_ID` — id папки для загрузки файлов
- `GOOGLE_CALENDAR_ID` — id календаря, в который добавляются события

Отладочные переменные:

- `GOOGLE_MOCK=1` — форсированно включит возвращение mock Google сервисов при старте (удобно для локальной разработки).
- `GOOGLE_STRICT=1` — при включении будет поднимать исключения/критические логи при отсутствии/некорректности ключа (рекомендуется для CI/production)

## 4. Поведение приложения

- По умолчанию `app/services/google.py` пытается инициализировать сервисы по `GOOGLE_SERVICE_ACCOUNT_FILE`.
- Если файл отсутствует или в нём ошибки — поведение зависит от комбинации флагов:
  - `GOOGLE_STRICT=1` — приложение будет логировать критические ошибки и выбрасывать исключение при проблемах с инициализацией.
  - `GOOGLE_MOCK=1` или режим разработки (`FLASK_DEBUG=true` / `FLASK_ENV=development`) — будет возвращён mock-сервис, который дает пустые ответы и не вызывает аварий.

Это позволяет разработчикам запускать локально сервис без доступа к реальным Google API.

## 5. Проверка и отладка

- После размещения файла выполните быстрый тест:

```powershell
python -c "from app.services.google import get_google_services; print(get_google_services())"
```

- Если увидите mock-сервисы — проверьте переменные окружения (`GOOGLE_MOCK`, `FLASK_DEBUG`) и путь к `GOOGLE_SERVICE_ACCOUNT_FILE`.
- При ошибке с текстом "Неверная подпись JWT" — скорее всего в `private_key` JSON поврежден или отформатирован неправильно (Windows CRLF/quote escaping). Откройте JSON в текстовом редакторе и убедитесь, что поле `private_key` содержит валидный многострочный ключ, начинающийся на `-----BEGIN PRIVATE KEY-----`.

## 6. Частые проблемы

- "invalid_grant" / "Неверная подпись JWT" — чаще всего связано с неправильным `private_key`.
- Недостаточные права — проверьте роли сервисного аккаунта в GCP.
- SPREADSHEET_ID указан неверно — откройте таблицу в браузере и возьмите id из URL.

## 7. Рекомендации для CI

- Для CI храните ключи в secret-менеджере (GitHub Secrets / GitLab CI variables / Azure Key Vault) и устанавливайте `GOOGLE_SERVICE_ACCOUNT_FILE` перед запуском.
- Альтернатива: сериализовать JSON в переменную окружения `GOOGLE_SERVICE_ACCOUNT_JSON` и записывать её в файл в рантайме (но тогда следите за безопасностью).
