# Редакционный чек-лист блога MyWave (перед `READY_TO_PUBLISH`)

**Назначение:** единые правила для редактора, Parser_News и владельца контента. Пока все пункты не выполнены, строку в `raw_feed` **не переводить** в `READY_TO_PUBLISH` / `PUBLISHED`.

**Связь с техконтрактом:** видимость на сайте — `docs/BLOG_CONTRACT_v1.md` (publishable v1). Этот документ — про **качество и структуру** текста, а не про код.

---

## 1. Обязательные поля (смысл)

| Поле | Требование |
|------|------------|
| **`title`** | Один заголовок статьи: без обрыва посреди фразы, без ведущих служебных эмодзи, без сырого Markdown (`**`, `` ` ``). Длина разумная (ориентир до ~90 символов для вкладки браузера). |
| **`final_posts`** | Финальный текст для страницы поста в **Markdown**: абзацы, списки, подзаголовки `##` / `###`, нормальные ссылки `[текст](url)`. Не «простыня» из одного абзаца без переносов. |
| **`excerpt` / `summary` / `lead`** | Plain text для карточки витрины (без Markdown, без длинных «голых» URL). Не дублировать целиком заголовок или первый абзац без смысла. |
| **`slug`** | Короткий, по смыслу латиницей; не вся первая строка поста и не предложение целиком. |

---

## 2. Структура материала (тело статьи)

Перед публикацией проверить:

- [ ] Есть **лид** (1–2 предложения): о чём текст и кому полезен — без копипасты из Telegram «как есть».
- [ ] Текст разбит на **абзацы** (не один блок на весь экран).
- [ ] Списки подарков / шагов / пунктов оформлены как **маркированный или нумерованный список** в Markdown, а не как строка с эмодзи между пунктами.
- [ ] Есть **подзаголовки** (`##`), если материал длиннее ~300–400 слов или логически делится на блоки.
- [ ] **Нет дублирования** одного и того же абзаца дважды.
- [ ] **Эмодзи** — по необходимости, точечно (не как разделители пунктов списка).

---

## 3. Что убрать или переформулировать

- [ ] Служебные фразы из соцсетей («собрали для вас топ…»), если они не несут смысла для читателя сайта.
- [ ] Повторы заголовка дословно в первом абзаце без добавления смысла.
- [ ] «Простыня» из импорта чата/поста без редакции под веб.
- [ ] Длинные голые URL в анонсе карточки — заменить на осмысленный текст + ссылка в теле статьи.

---

## 4. Источник и ссылки

- [ ] Блок **«Источник»** на сайте достаточно одного (мета + при необходимости ссылка в конце). Не дублировать один и тот же URL трижды в теле без нужды.
- [ ] Упоминания каналов (`@…`) — либо нормальная гиперссылка с текстом, либо вынести в конец.

---

## 5. Согласование с Parser_News

- [ ] **`final_posts` не пустой** до перевода в publishable-статус (техправило пайплайна).
- [ ] Карточные поля (`excerpt`, `summary`, `lead`, SEO) — **plain**, как в договорённости с Parser (нормализация при записи в Sheets).
- [ ] После правок — **обновление строки** в таблице, чтобы подтянулась нормализация старых черновиков.

---

## 6. Быстрый «стоп-крiterий»

Публикацию **отложить**, если:

- заголовок обрывается или выглядит как первая строка черновика;
- на странице поста один–два огромных абзаца вместо структуры;
- список читается только из-за эмодзи в одной строке.

---

## 7. Критерий готовности

Материал готов к **`READY_TO_PUBLISH`**, если редактор готов дать ссылку коллеге «как образцовую страницу блога» — без стыда за вёрстку текста и без объяснений «это так из телеги приехало».
