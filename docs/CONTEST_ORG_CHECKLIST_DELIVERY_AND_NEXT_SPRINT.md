## 0) Принятые DoD и критерии (зафиксировано Ярославом)

### 0.1 DoD чистой ветки

- В PR нет «случайных» правок (услуги/магазин/чат/аналитика/главная/другие проекты).
- В диффе только то, что относится к:
  - `/projects/contest-org-checklist`
  - PDF-генерации/скачиванию именно для чек-листа
  - редиректам со старых путей на каноник
  - изолированным print-стилям для этой страницы

### 0.2 DoD изоляции print-стилей

- Печать главной/любых других страниц не меняется.
- На странице чек-листа при печати:
  - скрывается навигация/шапка/кнопки/лишние элементы;
  - остаётся только контент (структура 1–10);
  - PDF и print имеют одинаковую логику «что видно/что скрыто».

### 0.3 Блокеры (без них не мержим) — подтверждает Subagent E

1. Страница `/projects/contest-org-checklist` открывается без ошибок (консоль чистая).
2. Секции 1–10 полностью соответствуют эталону по смыслу и структуре.
3. Чекбоксы/интерактивность работают предсказуемо (без «ломаний» вёрстки).
4. `/projects/contest-org-checklist/download` скачивает PDF: корректные заголовки, картинки видны, структура читаемая, нет обрывов/сломанных блоков.
5. Редиректы 301 со старых URL на каноник работают корректно.
6. Print-изоляция подтверждена: печать другой страницы ≠ печать чек-листа.

### 0.4 Не блокеры (фикс по возможности, не стопят релиз)

- Микро-типографика, дополнительные улучшения визуала.
- «Добавить ещё одну картинку/превью», если это не часть эталона.

### 0.5 Хвост Check1/Check11

Только если есть в эталоне — добавляем и проверяем в PDF. Если нет — не тянем.

- Print-стили изолированы под **страницу чек-листа**:
  - В `templates/base.html` добавлен блок `{% block body_class %}`.
  - На странице чек-листа задаётся `body_class`: `project--contest-org-checklist`.
