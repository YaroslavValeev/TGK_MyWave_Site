# Проекты на сайте: канон и реализация

## Ответ коротко (актуально после правок)

- **Канон:** в разделе «Проекты» — **5 карточек**: 1) WSC 2026 (WakeSurf Coach Challenge), 2) WakeSurf Safari, 3) Чек-лист для организатора, 4) Индустрия Wake, 5) Летний лагерь. Camp — только в «Услугах», не в «Проектах».
- **Реализация:** проекты из `configs/showcases/*.yaml` с `channels: [projects]`. Превью на главной — до 3 приоритетных (WSC 2026, Safari, Летний лагерь); жёсткая карточка «Тренировочная программа» убрана из карусели.

---

## Откуда берутся проекты

1. **Конфиги витрин (showcases)**  
   Файлы в каталоге **`configs/showcases/`** (YAML). Каждый файл описывает один проект/мероприятие. Загрузка: **`app/services/showcases.py`** → `load_showcase_configs()` → `list_showcases(channel="projects")` → **`get_project_cards()`**.

2. **Условие попадания в блок «Проекты»**  
   В YAML у проекта должен быть в списке **`channels`** значение **`projects`**. Тогда он попадает в `get_project_cards()` и на главную.

3. **Главная страница**  
   В **`app/__init__.py`** для главной вызывается:
   - `projects_preview = get_project_cards()[:3]`  
   То есть показываются **не более 3 проектов из конфигов**.

4. **Дополнительная карточка в разметке**  
   В **`templates/index.html`** в карусель проектов после `{% for p in projects_preview %}` вручную добавлена ещё одна карточка:
   - **«Тренировочная программа для подготовки»** (ссылка на `training_program_page`).  
   Она не из YAML, а зашита в шаблон.

## Сколько и какие проекты сейчас

### В конфигах (configs/showcases/)

| Файл                | id              | name                         | channels   |
|---------------------|-----------------|------------------------------|------------|
| sochi_camp.yaml     | sochi_camp      | Тренировочный кемп в Сочи    | projects, events |
| wakesurf_safari.yaml| wakesurf_safari | WakeSurf Safari 2025         | projects, events |

Оба имеют `channels: [projects, events]`, значит оба попадают в **«Проекты»**.

Итого из конфигов: **2 проекта**.

### На главной (карусель «Проекты»)

- **До 3 карточек из `get_project_cards()`** — т.е. оба из YAML: «Тренировочный кемп в Сочи», «WakeSurf Safari 2025».
- **Плюс 1 карточка из шаблона**: «Тренировочная программа для подготовки».

Итого на главной в карусели: **3 карточки** (2 из конфигов + 1 фиксированная).

### Ограничение [:3]

В коде задано `get_project_cards()[:3]`. Если в будущем в `configs/showcases/` появятся ещё файлы с `channel: projects`, на главной всё равно будут показаны только **первые 3** (порядок по имени файла в `sorted(SHOWCASE_DIR.glob("*.y*ml"))`).

## Что в проекте сказано про «должны быть» (документация)

- В **`docs/showcases.md`** описаны обязательные **поля** конфига витрины (`id`, `slug`, `name`, …) и то, что **`channels`** задаёт, где показывать (`projects`, `events`). **Количества или списка обязательных проектов нет.**
- В **`docs/RELEASE_QUESTIONS_AND_SUBAGENTS.md`** и других релизных доках для **Услуг** явно указаны «5 обязательных» карточек (Зал, Катер, Выезд, Camp, Консалтинг), для **Товаров** — «6 обязательных карточек». Для **Проектов** такого норматива нет: формулировки только в духе «проекты и последние новости видны», «превью проектов из configs/showcases».
- Итог: **по документации проекта не задано, сколько именно проектов должно быть и какие именно.** Задано только: проекты берутся из конфигов с `channel: projects`, на главной показывается превью (ограничение по коду — до 3 из конфигов + одна фиксированная карточка в шаблоне).

---

## Что «должно быть» по коду и конфигу

- **Источник истины** — YAML в `configs/showcases/`. Добавление нового проекта = новый YAML с `channels: [projects, ...]`.
- **Количество на главной** — ограничено кодом: не более 3 из `get_project_cards()`, плюс одна фиксированная карточка «Тренировочная программа» в шаблоне.
- Сейчас по факту: **2 проекта из конфигов + 1 фиксированная** = 3 карточки в карусели. Это согласовано с логикой кода.

Если нужно зафиксировать «должно быть ровно N проектов» или обязательный список — это нужно добавить в спецификацию/документацию; в коде затем можно проверять количество или наличие нужных `id`/`slug`.
